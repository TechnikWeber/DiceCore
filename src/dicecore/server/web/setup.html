What the camera saw

The boxes are what the engine found. A red box is a die it located but could not read — those are exactly the ones worth labelling under Training.

Source

Where the pictures come from. Start on Folder: it plays back images from a directory, so the whole of DiceCore works before any hardware arrives. picamera2 and rpicam are the Pi's own camera port, v4l2 is a USB webcam, and push means another machine sends the pictures here.

CSI camera module

A Pi only binds a sensor the firmware knows. The official modules are auto-detected; Arducam's are not — they need camera_auto_detect=0 plus an explicit dtoverlay= and a reboot. Picking it here writes that for you.

Live view for people outside the room

Off by default, and that is deliberate. Switched on, anyone who can reach this DiceCore can watch the tray at /api/v1/stream.mjpg — which is exactly what you want when you are playing with somebody who is not in the room and would like to see the dice land, and exactly what you do not want left running otherwise. It shares the reading's own frames, so it never competes with the camera; whatever else the camera can see, it shows.

What the system sees

Game mode

DiceCore reads dice; the mode reads the result. Which dice may appear, how the faces become an answer, and what goes on the screen in big letters. A mode that is not in the list is Build your own — or a table entry away.

Default players

Games are set up on the game screen, not here. This is the line-up used when a game is started without being asked — from the API, or by the panel's end-turn button in the lobby. The wizard on the game screen overrides it every time, so most tables never need to touch this.

Engine

What actually reads the dice. Classic counts pips and needs no training, but cannot read numerals. Model is a small network you train on your own dice under Training, and reads numerals too. Remote sends the picture to another DiceCore on the network and uses its answer — which is how a Pi Zero, where neither of the other two can run, still works. Automatic takes the model if one is loaded and the classic reader otherwise.

Tray

The landing area, and nothing else. Dice outside it are not looked at, which removes table edges, hands and the tower itself before any recognition happens — the cheapest accuracy win there is. Drag a rectangle on the picture below; the numbers follow. They are fractions of the frame (0 to 1), so they still mean the same thing after a resolution change.

Classic engine

The reader that needs no training. It finds the dice by contrast against the tray and counts the pips as dark blobs on a light face — so it reads six-siders, and honestly admits it cannot read the numerals on a d20. These knobs are the two things that differ per table: which way round the contrast runs, and how big a die is in the picture.

Fair play

After the number is read the tray stays watched. A hand reaching in is recorded; dice that are not what was read void the roll. This is tamper evidence, not tamper proof — see docs/ANTI-CHEAT.md for what it cannot do.

Settling

Knowing when the dice have stopped. A picture taken mid-tumble is worthless, and a fixed wait is wrong in both directions — too slow for a d6 that lands flat, too fast for a d20 that rolls off the ramp. So DiceCore watches how much the picture changes and reads once it has been quiet for a few frames in a row. Raise the threshold if a busy room keeps it waiting; raise the frame count if it reads too early.

What the table sees

A number on a small screen the instant the dice stop, and two lamps that say whose turn it is. Both are optional and both can run at once — the preview below is rendered whether or not anything is wired up yet.

Display

This is exactly what the panel shows:

Lamps and buzzer

Green: throw. Red: the tray is being read or watched — hands off. The buzzer marks the number arriving and your turn coming round again. Set a pin to -1 to leave that one out.

Two buttons on the header, so a chip can be spent and a turn ended without walking round to a browser. Wire each between the pin and ground; -1 leaves one out.

What is worth celebrating

A game that keeps its own score decides this for itself — a Kniffel, four successes out of six, a Farkle worth a thousand. These settings are the answer for everything else. Prefer one of the first two: they scale with what is on the tray, while an absolute total cannot be right for two dice and six at once.

Teach it your dice

Roll, glance, correct. Every confirmed roll is a training sample — there is no separate labelling tool and no command line. Aim for a hundred rolls to start with, and watch the thin faces below.

Every die can be learned, not only six-siders: d2, d3, d4, d6, d8, d10, d100, d12 and d20 are all in the vocabulary, and the label list offers whichever faces that kind has. What differs is how much rolling it takes — about ten confirmed examples per face, so a d6 wants sixty and a d20 about two hundred. The classic reader counts pips and cannot read numerals at all; teaching a model is exactly how a d20 becomes readable.

How it fits together. A set is one lot of dice photographed under one light — that is the unit you collect into. A model is what the engine actually loads, and it is trained from one or more sets at once. So you can collect your six-siders and a friend can collect his d20s on his own tower, and one model can learn both. The model knows exactly the faces that were in the sets it was trained from, and nothing else.

Three examples, start to finish

Ordinary six-siders. You may not need this at all — the classic reader counts pips without any training. Train only if your dice are unusual: dark, translucent, oddly inked. New set “white d6, kitchen lamp”, then roll and confirm about sixty dice — ten per face. Every throw of three dice gives you three.

Kniffel. Same as above, and five dice a throw means twelve throws gets you sixty. Tick keep rolling, throw, glance, correct, repeat. The engine usually has the pips right already, so most throws are one glance and no typing.

A roleplaying set. This is where training earns its keep: the classic reader cannot read numerals at all, so a d20 is unreadable until a model exists. Set the dice under Detection → Dice that may appear first, then roll the d20 on its own until every one of its twenty faces has come up about ten times — two hundred confirmed dice, an evening. Do the d8, d12 and the rest in the same set or in sets of their own; they can all go into one model either way.

Send rolls out — Discord, Avrae, anywhere

      
The other direction: instead of somebody asking DiceCore for a roll,
        DiceCore hands each finished roll over. All off by default, and two of these carry a
        credential that lives in the config file in plain text.


      

        

        

      


      
Avrae

      
The honest answer first, because it is the question everybody
        asks. When you throw a die here, Avrae does not silently produce the
        same number for whatever you type next. Avrae's dice are Avrae's, and
        !check athletics will always roll its own. Nothing can change that —
        not this project, not any other.

      
What happens instead: DiceCore writes each roll into an Avrae
        user variable, and an alias in Discord reads it back. You still type
        something — but the number in the answer is the one on your table. There are two
        shapes of alias below, and they differ in exactly that.

      
Get the token from
        avrae.io/dashboard,
        press Send a test roll to check it, then paste an alias into Discord once.

      

        

        

        

        

      

      
1 — show what I threw. Type
        !phys after a throw and Avrae prints it. Simple, and certain to work.

      

      


      
2 — make Avrae roll my number. This is
        the one people are usually after. It hands Avrae a die that can only land on
        what you threw (1d20mi17ma17 is a d20 clamped to 17), so the result goes
        through Avrae's own roller and comes out in Avrae's own format — bonuses and all.
        Type !pr +5 after throwing.

      

      

      
What I checked and what I did not. The API this writes to is
        verified against Avrae's own source. The aliases are not: I have no Avrae account to
        try them on, and the clamping trick in the second one relies on dice syntax that may
        have moved. Try them in a quiet channel first.
